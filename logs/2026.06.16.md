## CSI_DATA 확인

수신 보드 모니터 실행:

```bash
cd /Users/yoonjeongah/Desktop/NotiFi/esp-csi/examples/get-started/csi_recv
PATH=/opt/anaconda3/bin:$PATH
source /Users/yoonjeongah/esp/esp-idf/export.sh
idf.py -p /dev/cu.usbmodem101 monitor
```

수신 보드에서 실제 `CSI_DATA` 로그가 연속으로 출력되는 것을 확인했다.

예시:

```text
CSI_DATA,2192,1a:00:00:00:00:00,-88,11,-98,-10,79,11,107482,47,2,256,0,"[...]"
CSI_DATA,2193,1a:00:00:00:00:00,-88,11,-98,-11,79,11,118482,47,2,256,0,"[...]"
CSI_DATA,2194,1a:00:00:00:00:00,-90,11,-98,-8,79,11,129482,47,2,256,0,"[...]"
```

확인된 특징:

- 송신 MAC: `1a:00:00:00:00:00`
- RSSI: 대략 `-85 ~ -92 dBm`
- CSI 배열 길이: `256`
- `CSI_DATA`가 연속 출력됨

따라서 오늘 기준으로는 **CSI 데이터가 실제로 들어오는 것까지 확인 완료**했다.


```bash

```

확인된 출력:

```text
open success
none 256
```

의미:

- `open success`: 수신 보드 시리얼 포트를 정상적으로 열었음
- `256`: CSI 배열 길이가 256으로 들어오고 있음

## 중간에 발생한 문제

처음 그래프가 움직이지 않았다.

확인 중 나온 에러:

```text
read failed: [Errno 6] Device not configured
```

의미:

- 수신 보드 USB 연결이 순간적으로 끊겼거나
- 케이블/포트 연결이 불안정했거나
- 보드가 재연결되며 시리얼 포트가 끊긴 상황

조치:

- 시각화 프로세스를 종료
- 수신 보드 포트를 다시 확인
- `idf.py monitor`로 원시 로그부터 확인
- 이후 `CSI_DATA`가 들어오는 것을 확인한 뒤 그래프를 다시 실행

- CSV 저장 실험
- idle / hand_move / walk 비교

## 사람 움직임과 CSI 변화

CSI는 두 보드 사이 또는 주변 공간의 Wi-Fi 신호 상태를 나타낸다.

사람이 움직이면 Wi-Fi 신호가 반사, 흡수, 간섭되기 때문에 CSI 값이 달라질 수 있다.

변화가 잘 보이는 조건:

- 두 보드 사이를 사람이 지나감
- 보드와 사람이 너무 멀지 않음
- 두 보드 간 거리는 약 1m 이상
- 송신/수신 보드가 같은 높이 근처에 있음
- 외장 안테나가 있다면 안테나 방향이 안정적으로 고정됨

변화가 잘 안 보일 수 있는 조건:

- 사람이 보드 신호 경로에서 멀리 있음
- RSSI가 너무 약함
- USB 연결이 불안정함
- 송신 보드 전원이 불안정함
- 주변 Wi-Fi 간섭이 심함
